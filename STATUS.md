# Implementation Status

Snapshot of what splot currently does. Treat this as a complement to [ROADMAP.md](ROADMAP.md) (what's planned) and [CONFIG.md](CONFIG.md) (full config reference).

The code is a Cargo workspace of three crates:
- `crates/splot`, the binary `splot`: the CLI, the config, validation, the planners and the renderers.
- `crates/splot-agent`: everything splot does on a node (the key stores, the node check, applying and reloading on OpenWrt and Linux). A library so far, which splot calls in-process; a binary splot copies to the node comes with the controller.
- `crates/splot-core`: what the two share: the checked key and name types, `HostRef`, `Os`, the secrets' placeholders, uci's vocabulary (commands, sections, section names, slots, reading `uci export`), and the protocol (`Request`, `Reply`, the rendered payloads). splot uses core's types as if they were its own (`types::identifier`, `types::wg_key`).

Source paths below (`src/...`) are within `crates/splot` unless they name another crate.

---

## Done and working

### Config parsing

- YAML config loader at `src/config.rs` — deserializes `splot.yml` into typed Rust structs (`Config`, `Node`, `NodeZone`, `NodeHub`, `Client`, `Service`, etc.).
- Custom `OneOrManyUnique<T>` type — accepts a single value or a list in YAML, deduplicated into a `BTreeSet`. Used for `tags`, `macs`, `proto`, `allowFrom`.
- All config maps and sets are `BTreeMap`/`BTreeSet`, so iteration order — and with it validation output and generated UCI — is deterministic across runs.
- `deny_unknown_fields` on every config struct: a misspelled key anywhere is a parse error naming the config path, the unknown key, the valid keys, and the line/column.
- Typed IP / network handling via `src/types/ip.rs` (`Ipv4Addr`, `Ipv4Interface`, `Ipv4Network` with subnet membership / overlap predicates).
- Typed MAC handling via `src/types/mac.rs`.
- Typed node endpoints via `src/types/endpoint.rs` (`EndpointHost`): an IPv4 address or a DNS name (labels of letters, digits and hyphens, at most 63 characters each and 253 in all). A name whose last label is all digits is rejected: no top-level domain is, so it's a mistyped IP.
- Typed node platforms via `src/types/platform.rs`: `os` (`openwrt`, `linux`) and, per concern, a `Setting` that is a program (`WireGuardProgram`: `netifd`, `wg-quick`; `FirewallProgram`: `fw4`, `nftables`; `DhcpProgram` and `DnsProgram`: `dnsmasq`) or `none`. Each program knows which OS splot can manage it on. A name splot doesn't know for that concern is a parse error listing the ones it knows.
- Typed ssh destinations via `src/types/ssh.rs` (`SshDestination`): a node's `platform.ssh` and `--ssh`, kept as written for the system `ssh`; empty, a leading `-` (ssh would read an option) or a space or control character is refused.
- Typed WireGuard public keys via `splot-core`'s `wg_key.rs` (`WgPublicKey`): 44 characters of canonical base64 ending in `=` — the same rule `wg` itself enforces.
- Typed secret keys in the same file: `WgPrivateKey` and `WgPresharedKey`, two kinds of one `SecretKey<K>` (so each behaviour is written once, and one kind can't be passed for the other). Checked on parse like a public key; never shown: no `Display`, `Debug` prints `<redacted>`, and only `expose()` gives the text, where a key is written for WireGuard (the fill-in, the key store, `wg pubkey`'s input). They're parsed where they enter: the key store when it's read, `wg genkey`'s output, and the stdin of `splot psk set`.

### Key stores (persistent local state)

- A node's secrets live in its key store, one per platform behind the `KeyStore` trait (`splot-agent`'s `key_store.rs`): `load` (reads and checks the keys, writes nothing), `create_private_key` (only `init`), `store_psk`, `private_key`, `psk(peer)`, and `check_node` (this peer's key is the one the config has for the node). Its errors (`KeyStoreError`) are the same for every store.
- Which store a command uses is the node's OS: the config's, or for a node the config doesn't have yet, `init --os`, or else detected (the agent's `node::detect_os`: OpenWrt by `/etc/openwrt_release`, any other Linux as Linux). Any two that disagree is an error: `init` asks the agent which OS it runs (`Request::Os`) and refuses a peer that isn't what the config or `--os` says (`commands::peer_os`); the agent refuses to apply a config, or store a PSK, for another OS than the one it runs on (`node::check_os`).
- On Linux, `FileKeyStore` (`splot-agent`'s `linux/key_store.rs`): `/etc/splot/keys`, a line per key (`private-key <key>`, `psk <peer> <key>`, the peer as the config names it). Every write replaces the whole file atomically (a new file beside it, created 0600, renamed over it; `/etc/splot` made 0700 if missing). A line it doesn't hold, a second private key or a peer's second PSK is refused, naming the line.
- On OpenWrt, `UciKeyStore` (`splot-agent`'s `openwrt/key_store.rs`): the uci file `/etc/config/splot`. It stores the node's one private key, for the mesh interface (`splot.config.private_key`), and the preshared key of each of its pairs that has one, a `psk` section per peer named like the peer's own section (`splot.spl_psk_Cabin.key`). Stored PSKs are checked to be keys when it's read. The file is readable by root only (0600, as OpenWrt keeps its own files that hold secrets): splot makes it so before every write, so a new store is private before a secret goes in and one an older splot left readable gets tightened.
- `load()` reads the keys and checks them, and writes nothing: a router without a private key is told to run `splot init`. Only `init` creates the key (`create_private_key`), and only when there's none.
- A stored key is validated on load; a corrupt key is a hard error, never silently regenerated (regeneration would orphan the node's peers).
- Designed to grow as more local-only state is needed (e.g., last-applied config snapshot for distributed-reload rollback — see IDEAS.md).

### Config validator (`src/model/validator/`)

Multi-pass validator that checks `splot.yml` before any UCI commands are generated. Several passes, the first few producing data the next consumes:

1. **`platform`** — each node's platform: a concern left out takes the OS's default (OpenWrt: netifd, fw4, dnsmasq, dnsmasq; the defaults are in `consts.rs`), and is an error on Linux, which has none; a program the node's OS doesn't have is an error. A node whose WireGuard splot leaves alone has no hub (an error). A node whose platform fails is left out of the model.
2. **`names`** — collects global + per-node names; checks identifier syntax, namespace uniqueness, cross-namespace collisions, reserved prefixes (`spl_` and `{NodeName}_`); registers `{NodeName}.$hub` for nodes with a hub.
3. **`tags`** — collects valid tags; checks tag syntax and tag/name collisions.
4. **`entities`** — semantic checks: client IPs reference valid node/network, mac/publicKey required-iff-used, public keys unique across nodes / hub clients / global clients, unreachable clients.
5. **`networks`** — subnet uniqueness across mesh + zones; hub networks lie inside `meshNetwork`, don't overlap each other, and hold no `meshIp`; IP-in-subnet containment, and host IPs may not be their subnet's network or broadcast address (/31 and /32 excepted); IP uniqueness per mesh/zone/hub; `client.ips` ≤ 1 zone per `(client, node)`.
6. **`endpoints`** — at least one node has an `endpoint` (when there are several), a node without one has no hub, and each pair of nodes without one is a warning (no tunnel between them).
7. **`ports`** — per-host service-port uniqueness, the node's WireGuard listen port included, and external-port uniqueness on each router's WAN.
8. **`services`** — each service's references (`references.rs`): every `allowFrom` reference resolves to a known identifier, and a service with neither `allowFrom` nor `wan` is a warning; and its WAN exposure (`wan.rs`): each `wan.via` target resolves to a reachable destination, the qualified `{Node}.{Network}` form is rejected on non-client services, `wanZone` is declared where needed (on a `wan.via` node whose firewall splot manages: one that leaves it alone forwards nothing); declared-but-unused `wanZone` is a warning.
9. **`wanZone`** — doesn't collide with a zone or the mesh name.
10. **`unmanaged`** — what a node leaves undone because a concern is `none`, as one warning per node and concern, saying what's the operator's to do: a firewall left alone enforces no `allowFrom` there (the services its ingress rules would cover), forwards nothing from its WAN, and needs splot's mesh interface put into a zone of the operator's (when splot manages the WireGuard); WireGuard left alone means a firewall without a mesh zone, and no forward to a host reached over the mesh. A concern left alone with nothing asked of it is no warning, and neither are `dhcp: none` and `dns: none` (nothing undone yet).

Validation is how the checked model (`src/model/`) gets built: `model::validate(&Config) -> Result<Validated, ValidationReport>` returns a `Network` plus the warnings, or every error and warning. Only `validate` can make a `Network` (its fields are private to `model`), so whatever reads one can rely on what validation checked.

- The passes build the model's pieces while they check: what fails a check is reported and left out, and a `Network` exists only when nothing failed. Each piece is built once, whole, by the pass that knows all of it; nothing is filled in later.
- **Hosts** (`src/model/host.rs`), built by the `networks` pass: every node, zone device, hub client and global client, in config order, as a `HostRef` (in `splot-core`; its identity: `Node`, `Local { node, name }` or `Client`), its addresses, its MACs and its WireGuard key (hub and global clients). Each address is its IP with the prefix of the subnet it's on, checked to be a host there, and where it lives (`Zone { node, zone }`, `Hub { node }` or `Mesh`).
- **Nodes** (`src/model/node.rs`), built by the same pass: each router's name, its platform (`src/model/platform.rs`: the OS, and per concern the program splot manages it with, or none), key, endpoint (an address or a DNS name; none for a node nobody can dial) and listen port, its mesh address (its mesh IP with the mesh network's prefix, checked), its zones' subnets, its hub network and its `wanZone`. A node whose mesh IP or platform fails its check is left out; a zone or hub that fails its checks is left out of the node.
- **Services** (`src/model/service.rs`), each built whole by the `services` pass and kept in the `Network` by its host: the service's port, protocols, sources and WAN exposure. The sources are its `allowFrom` resolved to the networks each reference names, with where each lives: explicit tags, bare node names (the node's zone subnets and hub network), global client names (all their IPs), qualified `{Node}.{LocalName}` forms, a node's hub network (`{Node}.$hub`), and a node itself (`{Node}.$node`): its mesh IP and its own address on each of its zones, let in on every node but that one (what a node sends leaves through its output). `$node` is the node the rule is on, so it lets nothing in anywhere. An unknown reference is an error; a network two references name is listed once. The WAN exposure is: for every `wan.via` node, the host address it forwards to (a node's mesh IP; a device's or hub client's IP; a global client's mesh IP, else its IP on that node's zone, or the zone a qualified `{Node}.{Zone}` names), and the allowed source CIDRs. A target whose address failed its own check is left out, with no second error.
- The planner reads only the `Network`; a command finds its node there by the name `--node` gives. The raw `Config` is read by validation alone.

### Node plan (`src/plan/`)

What one node has to do, by concern, worked out from the `Network`, with no platform in it: `plan::plan(&Network, node) -> Option<NodePlan>`, where `NodePlan { node, public_key, wireguard, firewall, dhcp }`. The public key is the node's own, for the backend's key check. A section is there only for a concern splot manages on the node: one its platform sets to `none` has none. Each section comes from its own pure planner function, which takes the `Network` and the node (looked up once, by `plan`, so a planner only ever sees one of this network's nodes); DNS joins once it's implemented.

- **`wireguard`**: the mesh interface (listen port, mesh address) and its peers: every other node (routed, with its endpoint if it has one), every global client with a mesh IP, and this node's hub clients. Each peer carries its keepalive, which follows one rule: only a host nobody can dial that others connect to sends keepalives (every `keepaliveInterval` seconds, 25 by default; `0` turns none on), to keep its NAT mapping open for whoever connects to it. A node without an endpoint is one (the other nodes ping it), so it keeps alive toward the nodes it dials, the ones with an endpoint; a peer without one (a client, another node without an endpoint) gets none and decides for itself. A node with an endpoint sends none. The rule's client side (only a client that offers services) is for client profiles. Each peer also says whether the pair uses a preshared key: only when both ends want one (`psk`, on by default). No private key: the backend holds it.
- **`firewall`**: the mesh zone's policy (input and forward drop, output accept), the rules (ingress, then egress), the default policy (the node's splot zones and the verdict on what no rule accepts: drop), and the redirects. On a node whose WireGuard splot leaves alone there's no mesh zone, no rule from or to the mesh, and no redirect to a host reached over the mesh: they would name a zone splot doesn't have there.
- **`dhcp`**: a lease for every address a host with MACs has on this node's zones.
- Plan objects carry identity (a `HostRef`, the service, a rule's direction), never a backend's name for them: the OpenWrt renderer derives uci section names and labels from it.
- `NodePlan`'s `Display` is a plain-text view of everything in it, one object per line in config notation (`Home`, `Cabin.camera`), snapshot-tested per node of the example config.

### Firewall (planned in `src/plan/firewall/`, rendered by `src/backend/openwrt/firewall/`)

- **Zones (`zones.rs`)**: splot's one managed zone, the mesh zone (`spl_mesh`), rendered as a `config zone` UCI section. Everything that arrives over WireGuard is in it, hub clients included. Default policy `input`/`forward` `DROP`, `output ACCEPT`; access granted only via explicit service rules.
- **Rules (`rules.rs`)**: per-service `config rule` UCI sections for every host's services (node, device, hub client, global client), from the model's hosts: an ingress rule toward the host's addresses on this node, an egress rule toward its addresses on other nodes, from the sources behind this node. A global client's `meshIp` gets no rule yet. One rule per source zone: `src` is the zone the sources arrive in (one of the node's own, else the mesh zone), `dest` the host's zone, the mesh for a host behind another node, or none for the router itself (its input chain). No rule for sources in the destination's own zone (that traffic never passes the router), for the router's own zones toward the router (the operator's input), or for the node itself (`$node`, or `Home.$node` on Home: the node's output).
- **Deny (`deny.rs`)**: splot's default policy as `config rule` sections after its accepts, every protocol, `DROP`: whatever leaves the mesh zone (`dest '*'`), and from each declared zone into the mesh and into every other declared zone. fw4 puts each in its source zone's forward chain. What it drops, and the node's input from the mesh zone, go to the agent as what splot owns (`Rendered.owned`, `firewall::owned`).
- **The operator's sections where splot decides (the agent's `openwrt/contested.rs`)**: at the dry run, the agent reads the node's firewall file and warns about each of the operator's sections fw4 takes that overlaps what splot owns: a forwarding (from one zone it forwards nothing there any more, since fw4 checks rules first; from any zone it accepts first), and a rule with a verdict (accept, drop, reject, read as fw4 reads a target), which decides before splot's. Each warning names the section as uci does (`firewall.@forwarding[1]`), where it overlaps (`from lan to spl_mesh`), and what to do instead.
- **Redirects (`redirect.rs`)**: `config redirect` (DNAT port-forward) UCI sections for services that declare `wan`. `wan.via` selects which routers expose the service via their `wanZone`; each forwards to the target the model resolved for it (see the `wan` pass above), in the mesh zone for mesh and hub addresses. Forwarding to a host on another node names the mesh zone, but doesn't work yet: the host's node lets none of it in, and the reply doesn't come back through the entry node. `wan.sources` (the CIDR allowlist) is applied as the redirect's `src_ip`: empty/missing means publicly reachable, a non-empty list restricts the forward to those CIDRs.

### WireGuard (planned in `src/plan/wireguard.rs`, rendered by `src/backend/openwrt/network.rs`)

- Generates the `config interface` UCI section for the node's one WireGuard interface, the mesh interface (`spl_mesh`).
- Peer sections (`config wireguard_spl_mesh`):
  - each remote node, with `AllowedIPs` = its `meshIp`, its zones and its hub network (even while the hub is empty);
  - each global client with `meshIp`;
  - this node's own hub clients (peers on their hub node only).
- Includes WireGuard-specific knobs: `listen_port`, `private_key`, `addresses` (the option OpenWrt's WireGuard handler reads; not `address`), `public_key`, `endpoint_host` (an address or a name: OpenWrt resolves a name when the interface comes up, and one that doesn't resolve keeps the whole interface down, every peer with it), `endpoint_port`, `allowed_ips`, and `persistent_keepalive` only for a peer the plan gives a keepalive (on a node without an endpoint; a missing option is netifd's "off").

### DHCP (planned in `src/plan/dhcp.rs`, rendered by `src/backend/openwrt/dhcp.rs`)

- Generates `config host` UCI sections for static DHCP leases.
- Sources:
  - Zone devices with `macs` — one lease per zone IP, attached to each declared MAC.
  - Global clients with `macs` and zone IPs on the current node.
- Lease ties MAC to the zone IP so the device gets a predictable address every connection.

### Backends (`src/backend/` renders, `splot-agent` applies)

- splot renders a node's plan as its platform's config (`backend::render(&NodePlan, Os)`: pure, snapshot-tested), a `Rendered` payload of `splot-core`'s protocol: `OpenWrt` (uci sections file by file, and the slots where the secrets go) or `Linux` (the wg-quick file). `main` is load → validate → plan → render → the agent.
- The agent (`splot_agent::Agent::handle`) takes `Request::DryRun`, `Prepare` and `Go` (see Runs below) and answers `Reply::DryRun` and `Prepared` (both `Changes`: each change in a few words, as apply reports it, and the dry run's text, computed the same way), `Applied(what changed)`, or `Failed(the error and its causes)`, which `commands::apply` prints the way it did before (an agent error keeps its causes). splot calls it in-process for now. The agent first checks it runs on the OS the payload is for, then that it's the node (`node::confirm_node`: by the key store's key, or by the peer's own WireGuard where splot leaves it alone), and fills the secrets in from the key store (`secret`), refusing a pair whose PSK isn't stored.
- OpenWrt (`src/backend/openwrt/` renders; the agent's `openwrt/` applies): the plan as the `network`, `firewall` and `dhcp` uci files, applied with uci (below), the services reloaded. Its key store is `UciKeyStore`. A file is rendered only for a concern splot manages: one left alone (`none`) has no file, so apply stages, deletes, commits and reloads nothing there.
- Linux (`src/backend/linux/` renders; the agent's `linux/` applies): WireGuard only so far. It renders the plan's WireGuard section as the wg-quick file `/etc/wireguard/spl_mesh.conf` (`wg_quick.rs`, snapshot-tested for Barn): `[Interface]` (address, listen port, private key) and a `[Peer]` per peer, commented with its name in config notation (public key, PSK, AllowedIPs, endpoint, keepalive). Apply (`apply.rs`) writes the file with the secrets in (0600, atomically) only when it differs, then has systemd make it live: `enable --now wg-quick@spl_mesh` when the unit isn't running; `restart` when the interface's live address or routes (`ip -j`, the kernel's own route aside) differ from what wg-quick sets from the file (the allowed IPs outside the address's network), saying why; `reload` (`wg syncconf`) when only the file changed; `enable` when it runs but isn't enabled. It refuses an interface of that name up without the unit. The dry run prints the file, masked, and those steps. `commands::check_applicable` refuses a Linux node whose firewall or DHCP names a program. Its key store is `FileKeyStore`.

### Applying on OpenWrt (`splot-agent`'s `openwrt/apply.rs`, `uci.rs`)

- Apply is the whole OpenWrt apply — check, stage, commit, reload — so `main` only reports the result.
- Apply refuses to start while `network`, `firewall` or `dhcp` has uncommitted uci changes. uci keeps staged changes in one place per file, shared by every uci user on the router, so splot would commit (or revert) someone else's changes together with its own.
- It reads each file's current state with `uci export` (not `uci show`, which prints a one-value list exactly like an option) and diffs splot's sections against the rendered ones (`diff.rs`). The diff yields logical changes (a section added or removed, an option set or removed, splot's block reordered) that point at the sections they're about; uci commands are produced from them only right before staging, in one place that knows how uci spells them. It stages only deletes for sections that are gone, whole new sections, `set` for changed options, whole-list replacements for changed lists, and `reorder` when splot's sections are out of order. splot's sections stay one block after the operator's, in plan order; the operator's sections are never touched. An unchanged config stages nothing: no batch, no commit, no reload, and the files aren't rewritten.
- What differs is staged in one `uci batch` without commits. `uci batch` exits 0 even when it rejects a line — it prints the error to stderr and carries on — so any stderr output counts as failure: splot reverts its staged changes and commits nothing.
- `--dry-run` prints exactly what would be staged (`# Nothing to change.` when nothing would), with the private key as its placeholder.
- Only then does it commit the files that change, one by one. Commits across files aren't atomic: if one fails (e.g. a full flash), the files before it keep the new config, and the error says which.
- The uci module exposes plain functions (`get`, `export`, `has_changes`, `batch`, `commit`, `revert`) over a shared `run()` helper with typed errors (`uci::Error`): spawn failures, I/O errors, non-zero exits and rejected input (stderr output) are distinguished, and uci's exact `Entry not found` message is classified as legitimate absence (`Ok(None)`) rather than failure.
- Values go into batch commands in single quotes with every `'` escaped the way uci reads it back (`it's` → `'it'\''s'`), so no value can end its quote and add a command of its own. `batch` also refuses, before sending anything, a command whose path has a character uci names can't have (paths aren't quoted) or whose value has a control character; the error names the path, never the value, which may be a key. Every value splot sends comes from a checked type, so both are guards against bugs.
- The node's private key is never in what's rendered: the plan has no key, so the rendered config holds a placeholder (`<private key>`) where it goes, and so do the snapshot and the dry run. The same goes for each pair's preshared key (`<preshared key>` in the peer's `preshared_key`). What's rendered also records where each secret goes (its slot: file, section, option): `apply` fills the secrets in from the key store just before staging, each into its slot only, and the dry run shows a `set` of a slot as the placeholder again. Apply and the dry run refuse while a pair that uses a PSK has none stored, naming the peers, before touching anything. Neither looks at what a value looks like. The placeholder isn't a valid key, so it can't pass for one.

### Reloading services after apply (`splot-agent`'s `openwrt/reload.rs`)

- `uci commit` only writes files. After committing, splot reloads the services of the files that changed (those the diff touched) and reports any failure; nothing changed → no reload.
- `reload_config` reloads every service whose config changed: fw4 for `firewall`, dnsmasq for `dhcp`, netifd for interface-level changes (key, port, addresses). procd runs these reloads a second later.
- netifd's reload doesn't see peer changes (peers are separate `wireguard_<interface>` sections), so when `network` changed, splot runs `ubus call network reload` (netifd re-reads the config now, so new interfaces exist) and then updates each of its WireGuard interfaces. It asks netifd first (`ubus call network get_proto_handlers`) whether the WireGuard handler supports renew:
  - yes (OpenWrt 25.12+): `ubus call network.interface.<iface> renew` re-runs the setup with `wg syncconf`; live, tunnels stay up.
  - no (24.10): `down` + `up` on the interface; the tunnels drop for a moment.
- Every command is a request to procd/netifd that returns at once; the daemons do the restarts afterwards, independently of splot's session, so a reload that briefly drops the mesh can't cut splot off halfway. splot runs all commands even after one fails, then reports every failure.
- `apply` fails before writing anything when `ubus` isn't available. `--dry-run` lists the reload commands as `#` comments, which `uci batch` ignores.

### CLI (`src/cli.rs`, `src/main.rs`, `src/commands.rs`)

- Every command that acts on a node goes through the agent (`commands::ask`): `init` asks for the OS (`Request::Os`), then for the key (`Request::Init { os }`: made only if there's none; the agent answers the public key and whether it just made it), and holds that against the config itself; `psk set` checks the peer and reads the key, then sends it (`Request::StorePsk`) to the agent, which checks the OS and the node before it stores it; `apply` sends the rendered config (`Request::Apply`). An answer to another question is an error.
- clap-based CLI: `splot init --node <Name>` (gives the peer its key if it has none, and holds the key against the config: initialised; a new key to set; an entry to paste for a node the config doesn't have, with the lowest free mesh IP; refused when the key is another entry's, named by its config path, or when an existing key is nowhere in the config; the only command that writes the key), `splot check` (validate, report errors/warnings), `splot apply [--node <Name>] [--dry-run | --yes]`, and `splot psk set --node <Name> <peer>` (store the preshared key of the node's pair with a peer, read from stdin; refuses a name that isn't its peer, a pair with `psk: false`, and anything that isn't a key); `-c/--config` overrides the config path (default `splot.yml`).
- `main` parses the command line, loads and validates the config (every command does that first), and dispatches; each command is a function in `commands` (`init`, `apply`, `psk_set`).
- Only OpenWrt nodes can be applied to for now: `apply` and `psk set` refuse a Linux node, and `init` one the config says isn't OpenWrt; `check` validates all of them.
- A node whose WireGuard splot leaves alone (`wireguard: none`) needs no key of splot's: `apply` loads no key store there, `init` says there's nothing to initialise, and `psk set` refuses (splot sets up no peers there). The OpenWrt backend checks such a node by its own WireGuard instead: one of the peer's interfaces must have the config's `publicKey` (`wg show all public-key`; no private key is read).
- `main` returns `anyhow::Result` — errors propagate with context chains (thiserror-typed at module boundaries, anyhow at the application layer); validation failures and an unenrolled router abort with actionable messages.
- Every error type derives `thiserror::Error` (so each is a `std::error::Error`; a test lists them and stops compiling when one isn't). The parse errors of `src/types/` reach the user through serde, which shows only `Display`, so their messages include the inner reason, and that reason isn't also marked as their `source` (a chain would say it twice); a variant that only forwards an inner error is `transparent`. Snapshots pin every parse error's and every validation error's message. `ValidationWarning` keeps a hand-written `Display`: a warning isn't an error.
- Logging via `log`/`env_logger` (`info` progress per manager, `debug` for details).

### The agent binary (`splot-agent`'s `main.rs`, `scripts/dist.sh`)

- `splot-agent` answers requests on stdin, one JSON value a line, each with its reply on a line of stdout (`serve`), until stdin ends. A line that isn't a request it knows is answered with a failure saying so ("is it as new as splot?"), and the next is answered all the same.
- `scripts/dist.sh` builds it for every CPU splot supports (`aarch64`, `armv7` hard float, `riscv64`, `x86_64`) into `target/agents/<cpu>`: the `agent` profile (size-optimised, LTO, `panic = abort`, stripped), static musl, linked by Rust's own `rust-lld` (no cross toolchains; riscv64 needs `+crt-static`, the others are static by default). It checks each stays under 1 MB (it runs from a router's RAM) and, where qemu-user is installed, that it answers a request. 630–775 KB each today. It then builds splot (static, x86_64) with `SPLOT_AGENTS` naming them, which `build.rs` embeds, and checks every agent is inside it byte for byte (the linker drops what nothing uses): `target/dist/splot`, about 7 MB. `splot --version` lists the CPUs it carries agents for.

### Runs: confirm or put back (`splot-agent`'s `run.rs`)

- `apply` (not the dry run) is a run with an ID and `--confirm-within` (default 120 s, at least 10), in two steps. `Request::Prepare` begins it and changes nothing: the agent works out what differs, and keeps what the node has in `/tmp/splot/run/` (0700; `info.json` 0600: the backup holds secrets): the uci files that change, as they were (or that they weren't there); on Linux the wg-quick file and whether `wg-quick@spl_mesh` was active and enabled. The directory is the lock: another run is refused while one is in progress. The agent holds what it prepared in memory, and `Request::Go`, over the same session, applies it (`NotPreparedHere` otherwise). A run begins even when nothing changes, with nothing to put back, so that across nodes every node is prepared first and checked after, changed or not. When no node would change anything, splot begins no run ("Nothing to change.").
- It starts the watchdog: the agent's own program (or splot itself, applying locally) started again with `SPLOT_WATCHDOG` naming the directory, in a process group of its own, its stdio closed: it outlives the session. Each second it looks: decided already, it ends; at the deadline it rolls back.
- Each step is decided once, by renaming the run's one marker: `prepared` to `armed` (the go), then to `confirmed` (`Request::Confirm`), or to `rolling-back` (`Request::Rollback`, or the watchdog); a prepared run rolled back or at its deadline becomes `cancelled`, putting back nothing. A rollback tries `prepared` before `armed`, so a go racing the deadline never leaves a change applied with nobody to put it back. `rolling-back` restores the files and makes them live again (OpenWrt: the services reload, `spl_mesh` restarted or renewed if it's still there; Linux: the unit restarted or stopped, enabled or disabled, as it was). `/tmp/splot/last` says how the last run ended; a confirm after a rollback is "too late". A rollback asked again, or while the watchdog puts the run back, answers `RolledBack` all the same; a confirmed run refuses it (`Confirmed`).
- An apply that fails after the run began (a rejected batch, a failed commit, reload or systemctl) is rolled back on the spot, and says so.
- The health check: a run carries its probes, the node peers with their public keys and mesh IPs (from the plan). When the run begins, the agent pings them (a second ping for an idle tunnel, up to 16 s more for a peer it holds a session with, which the other end may have dropped) and keeps those that answered; splot, after a new session, asks it to check (`Request::Check`): it pings those again, each until it answers or 30 s have passed (less when the deadline is closer). splot names the peers that didn't answer before the run, so aren't checked, and confirms only when all the others still answer; otherwise it rolls back and names the peers the change cut the node off from. A node that can't run `ping` refuses to apply (it couldn't check).
- A peer whose preshared key changed gets a fresh session: WireGuard keeps a session until its next rekey, so the check would pass with a wrong key. On OpenWrt the diff gives the peers (`diff::psk_changed`), on Linux the old and new wg-quick files do (for a reload: a start or a restart keeps no session); the agent drops each from the live interface (`wg set … peer … remove`) just before the reload, which adds it back.
- splot confirms after a new session (the old one dropped), and says so: see "Runs across the mesh", which a run on one node is too.

### Runs across the mesh (`src/mesh_run.rs`)

- `splot apply` without `--node`: every node splot manages something on (`members`: one with every concern `none` is left out), each reached at its `platform.ssh`; a node without one is refused, naming all of them, and so is a Linux node splot can't apply yet, before any node is reached.
- `splot apply --node X` is the same run on a mesh of one (`apply_node`): X reached at `--ssh`, else its `platform.ssh`, else in-process; no run where splot manages nothing on X. It asks first too (`--yes`). Where the mesh's messages say "every node", they name X (`Mesh::worded`), and its error follows what failed on the same line (`Mesh::listed`).
- Each step runs on every node at once (`Mesh::each`, a thread per node, results in the nodes' order), but `Prepare` and `Check`, which ping the peers, run one node at a time (`Mesh::in_turn`), and each is printed after: the dry run of each (its identity checked there) as the plan (`== Home: network, firewall`, then its text; `== Cabin: nothing to change`), then each node's warnings (`warning: Home: firewall.@forwarding[1] forwards nothing …`, on stderr); "Apply this plan? [y/N]" (`--yes`; no terminal without `--yes` is refused first); `Prepare` (compared with the plan shown); `Go`; a new session per node, opened at once (`Agent::connect`), and `Check`, until a node isn't healthy (`Didn't check Home: no node keeps the change anyway`); `Confirm`, asked again over a new session while splot can't reach the node and there's time.
- One at a time because two ends that ping each other at once, neither with a session (after a preshared key changed on both, or an idle one expired), each start a handshake, and WireGuard, keeping one per peer, drops both answers and tries again 5 s later; where the nodes share a kernel (the mesh check's containers) the retries keep colliding, past the check's 30 s. In turn, a node finds the sessions the nodes before it opened.
- Failures: a prepare that fails or no longer matches the plan, a failed go, a lost peer or a node splot can't check: every node that may have the run is put back (`Rollback`, asked again over a new session if the session was lost). What each meant for that node: "put back", "nothing applied" (prepared, cancelled), "nothing to put back" (no change, or never prepared). A node splot can't reach is waited for until its deadline has passed (plus 10 s), then asked again: "put back by itself", or "still unreachable". A confirm that fails: the same wait, then the confirm asked again ("kept the change", or why not); the error says which nodes didn't keep it, and to run again.
- `agent::lost` tells splot losing a node (a `session::Error` in the chain: what was asked may be done) from the agent refusing.

### Reaching a node over ssh (`src/agent/`)

- `apply --node`, `init` and `psk set` reach the node at `--ssh <destination>`, else at its `platform.ssh` (`types::ssh::SshDestination`, checked the same way for both: no leading `-`, no spaces or control characters), else in-process; `--local` forces in-process (`cli::Reach::destination`). `--agent <file>` needs a destination from either. `Agent::Local` calls the agent's code in-process; `Agent::Remote` opens a `Session` at the first request.
- The session runs `ssh -T -- <destination> <bootstrap>`, with ssh's stderr on the terminal (password prompts, host keys, why it failed). The bootstrap says the node's CPU; splot picks the agent (`embedded::for_node`: `uname -m` and OpenWrt's `DISTRIB_ARCH`, armv7 only with a floating-point unit), sends its size and bytes into a 0700 `mktemp` file in `/tmp`, waits for `ready`, and sends `Hello { protocol }` before anything else. The file is removed when the agent ends (its input ends with the session); one that arrived shorter than announced doesn't run. ssh's exit 255 reads as "ssh couldn't reach it".
- Tested by running the same bootstrap with a local `sh` and a fake agent (a shell script): the copy in `/tmp`, its mode, its removal, a refused protocol, how a session ends, a cut-short upload.

### Running programs (`splot-agent`'s `process.rs`)

- Every program splot drives (`uci`, `wg`, `ubus`, `reload_config`) runs through one helper, `process::run`: it pipes the program's input and output, writes the input from a thread while the output is read (written first, it would block for good on a program that prints before it has read all of it: `uci batch` printing an error per line of a large batch), and tells a program that couldn't start from one that failed while running. A program that stops reading its input and then fails reports its own exit and output; one that stops reading yet claims success is an error, since what it read can't be trusted. Each caller keeps its own error type and messages.

### WireGuard key handling (`splot-agent`'s `wg.rs`)

- Generates new private keys via `wg genkey` (a `WgPrivateKey`).
- Derives public keys from private keys via `wg pubkey` (a `WgPublicKey`).
- Failures are typed errors (`wg::Error`): a missing `wg` binary, a non-zero exit (with wg's stderr), non-UTF-8 output, or output that isn't a key — never a panic or an empty key.
- Used by `splot init` (to create the key and report its public key) and by the key check: before a command acts as the node `--node` names, the key store derives this peer's public key and compares it with the one the config has for that node (the plan carries it). The OpenWrt backend runs the check first in the dry run and in apply (the rendered config carries the node and its key, so it can't be skipped); `psk set` has the agent run it before storing. A mismatch names this peer's key and points to `splot init`, which says whose key it is.

### UCI section naming (`src/backend/openwrt/section.rs` `UciSection`; `UciSectionName` in `splot-core`'s `uci/naming.rs`)

- Section names are a uci concern. The OpenWrt renderers implement `UciSection` on the plan objects (the mesh interface and zone, rules, redirects, leases, and peers via `PeerSection`): its file, its uci section type, an id derived from the object's identity (what tells it apart from other sections of the same type), and its options. Other backends will name things their own way.
- The section name is derived from that, the same way for every type: `spl_<section type>_<id>`, e.g. `spl_rule_in_Home_ssh`, `spl_redirect_Home_nas_https`, `spl_zone_mesh`, `spl_host_printer`, `spl_wireguard_spl_mesh_Phone`. uci has one namespace per file; the type keeps sections of different types apart. A rule's id includes its direction (`in`: traffic to this node's hosts; `out`: from local sources to other nodes); cross-node rules are namespaced by node name (`spl_rule_out_Home_printer_ssh`).
- Labels are in the config's notation, so what LuCI shows can be searched for in `splot.yml`: a rule's `name` (`[SPLOT] in: Home ssh`, `[SPLOT] out: Cabin.camera rtsp`), a redirect's (`[SPLOT] Home.nas https`), a peer's `description` (`[SPLOT] Home.lte-cam`). Section names keep uci's character set.
- Exception: an interface's section name is the interface name (`spl_mesh`). Zone `network` lists and peer section types refer to it, and netifd names the WireGuard device after it (at most 15 characters).
- `UciSectionName` does the mechanics: the `spl_` prefix (declared in `consts.rs`) keeps splot-managed sections apart from operator-managed ones, parts are joined with `_`, and `-` is mapped to `_` by `uci::name` (uci rejects `-` in section and option names).
- Safety net: apply refuses a rendered config that holds the same section twice in one file (`find_duplicate_sections`, on the sections themselves), instead of letting uci merge the two into one. It runs before splot touches uci at all.

### Tests (`cargo test`)

Unit-test suite over the deterministic core (~380 tests). Covers: type parsers (`src/types/`), config parsing (`src/config.rs`), all validator passes and the model they build (hosts, reference resolution, WAN targets; `src/model/`), the planners and the plan's plain-text view (`src/plan/`), the uci renderers (firewall zone/rules/redirects, network, dhcp), UCI command/builder rendering, the uci not-found classification and the private-key fill-in, and private-key validation. Tests are inline `#[cfg(test)] mod tests` at the bottom of each module; config-level cases build fixtures from YAML via `serde_norway` with shared helpers in `src/test_support.rs` (plus a test-only `UciKeyStore::for_tests` constructor). The process/IO layer (uci process execution, wg, the key store, env, the OpenWrt apply) is intentionally out of scope — to be covered later as integration tests. Conventions: [CLAUDE.md → Testing](CLAUDE.md#testing).
